## 笔迹代码拆分为独立 crate `viewink`（模块化）

用户要求把笔迹（handwriting/ink）相关代码模块化，不要全堆在一个代码库里。
明确目标：拆成独立 crate `viewink`，范围 = 笔迹算法 + 渲染管线，不含任何前端代码
（UI 面板、iced 事件处理、subscription worker 留在主 crate `viewstage`）。

落地结构（workspace 成员 `viewink/`）：
- `viewink/src/ink/`：`stroke`、`tessellator`（笔锋）、`mesh`（GPU 线段网格）、`history`（撤销）
- `viewink/src/live.rs`：`LiveCanvasState` / `LiveTransform` / `EraserCursor` / `StaticStrokeRef`（分层渲染共享状态）
- `viewink/src/render/annotation.rs` + `annotation.wgsl`：批注层 wgpu 渲染管线（iced `Primitive`/`Pipeline` 也留在 viewink，避免重复造桥）
- `viewink/src/gpu/mod.rs`：从原 `render/common.rs` 抽出的共享 GPU 原语（`StrokeSeg`/`StrokeGeometry`/`ViewTransform`/`Globals`/辅助）；**剔除**摄像头专用的 `PaddedPlaneUploader`（留在主 crate `src/render/padded_plane.rs`）
- `viewink/src/stats.rs`：渲染统计

主 crate 残留：前端/编排（`main.rs` 的 App、`AnnotationProgram`、笔/橡皮输入 handler、`stroke_compute_worker`、`build_annotation_layer`、`StrokeTaskSender`/`StrokeComputeTask`/`CachedStrokeMesh`）、`views/pen_panel.rs`、`render/camera.rs`、探针 `render/probe.rs`。

注意：`viewink` 目前是 workspace 内兄弟 crate（同仓库），用户若想要真正独立仓库需另行讨论（git submodule 等）。

## 手势与坐标完全重写为新 crate `viewcore-touch`

用户要求手势与坐标完全重写，创建新 crate `viewcore-touch`（位于 `crates/viewcore-touch/`），重点围绕高性能、高帧率、低功耗、低开销。

落地结构（**零依赖**，纯 std，`#![forbid(unsafe_code)]`）：
- `pointer.rs`：`PointerEvent`（16B Copy）/ `PointerPhase` / `PointerSource` + `PointerTable` 固定 8 槽数组指针表（替代旧 HashMap，O(8) 线性扫描）。
- `recognizer.rs`：`Recognizer` 单入口状态机 `on_pointer(ev) -> Gesture`（Copy 输出），指针表 + V2 捏合合并，无中间事件向量。
- `pinch.rs`：V2 增量捏合语义移植；激活容差判定全部在**平方距离域**（激活前 0 次 sqrt，每产出增量仅 1 次）。
- `transform.rs`：`ScreenTransform`（screen↔canvas、`pinch_anchor` 除法换倒数、`apply_pinch` 带锚点钳位 0.1..10）。
- `momentum.rs`：惯性 f32 重写；**位移按 dt_units 积分**（真正帧率无关，旧实现位移不随 dt 缩放，节拍变化速度会漂移——测试暴露后修正）；静止时 tick 立即返回 None。
- `batch.rs`：帧批处理（Down/Up 先行 + 每 ID 仅最新 Move + ID 升序；仅跟踪前 2 指，与旧行为一致），固定栈数组零分配。

旧实现清除的死状态/死代码（重写前逐一验证）：
- `first_finger_time`（只写不读，导致每次 Down/Up 各一次 SystemTime::now() 系统调用）。
- `is_pending` 分支从未被置 true（V1 遗留）；`finger0/finger1` 只写不读。
- 旧 `InputSource` 每事件分配 Vec<InputEvent>、`active_events()` 分配 Vec<&>、HashMap 哈希开销——全部移除。

主 crate 重接：
- `sys/touch.rs`：改产 `viewcore_touch::PointerEvent`；新增 `drain_events_into(&mut Vec)`（复用 App 的 `touch_scratch` 缓冲，稳态零分配）；删除本地 RawTouchEvent/PointerSource 定义。
- `main.rs`：删除 `mod gesture`；App 字段 `input_source`+`pinch_zoom` 合并为 `gestures: Recognizer`；RawTouchStart/Move/End 重写为单入口调用；`screen_to_canvas` 走 `ScreenTransform`；momentum.start/tick 全 f32；`process_touch_events` 用 `batch::batch_events`（事件 Copy，无 clone）。
- `src/gesture/` 已 `git rm`（6 文件删除），新 crate 8 文件已 `git add` 暂存（未提交）。

验证：`cargo test -p viewcore-touch` 21/21 通过；workspace `cargo test` 全绿（主 crate 14/14 含全部 GPU 渲染探针）；`cargo check` 零 warning；全仓无 gesture 旧引用残留。

经验：
- 事件/坐标路径的性能优化优先级：去分配（Vec/HashMap/clone）> 去系统调用 > 去浮点宽度转换 > 去超越函数；每项都要有可测证据（如 60Hz vs 120Hz 惯性总位移对比测试）。
- "帧率无关"必须同时覆盖摩擦与位移两项积分，只修摩擦是假无关（会被单元测试抓出来）。
