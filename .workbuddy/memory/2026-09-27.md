## 批注渲染性能优化（参考希沃 WPF 批注框架，改动落在 Viewstage-dev）

用户澄清：`D:/希沃视频` 是**参考工程**（希沃 EasiNote 批注框架，10.7 万行 C#/WPF/net45，本机无法编译：外部 HintPath DLL 缺失 + 无 sln），实际改动目标是 Viewstage-dev。

### 从希沃架构提炼的对照结论
- 希沃好的设计（Viewstage 已具备对等物）：动态墨迹独立容器/独立渲染线程（HostVisual+VisualTarget+DynamicRendererThreadManager）≈ 我们的 canvas 零消息热路径；每 16 点成批固化为 StrokeVisual ≈ LIVE_STROKE_BATCH=16；晾干交接（drying + NotifyOnNextRenderComplete）≈ 静态快照快照机制。
- 希沃的**反面教训**（我们避开了）：`StrokeTipVisual.Redraw()` 每个 stylus 包都全量重建笔尖几何 + RenderOpen，240Hz 下约 75% 是纯浪费。
- 希沃**缺失**而我们补上的：静态内容离屏/可见性缓存——希沃每个 Ink 元素 OnRender 直接 `InnerStroke.Draw()`，高笔迹量时全量重放且无剔除。

### 落地的四处改动
1. **视口剔除（收益最大）**：`StaticStrokeRef` 增 `bounds`（几何 AABB，含半宽外扩，快照构建时算一次）；`LiveCanvasState` 增 `viewport`（canvas draw 每帧写）；`view_to_canvas_rect`/`expand_rect`/`rect_contains`/`collect_static_segs` 公开。缓存矩形 = 视口外扩 25%，小幅 pan/缩放零重建。
2. **静态层单缓冲合并**：取消 128 笔分批（每批独立 create_buffer + bind group），改为单个 grow-only 缓冲 + 一次实例化 draw；`StaticUploadSlot` 复用缓冲（稳态零 create_buffer、零 bind group 重建）。
3. **采集抽稀**：`append_pen_point` 丢弃 <0.35 屏幕像素的抖动点（按 scale 换算到画布坐标）；判据是"与已保留最后一点"的距离，不累积漂移。
4. **镶嵌零分配**：新增 `tessellate_live_range_into`（采样点缓冲由调用方持有跨帧复用，旧 `tessellate_live_range` 保留为分配版包装）；几何 segs 按采样点数 `with_capacity`。
5. 合成层：稳态不再每帧 `Arc::clone` 静态快照（改为 borrow + ptr 判定）。

### 实测（cargo test --release -p viewgfx --test perf，A/B 同轮）
- 视口剔除：静态层每帧段数 840000 → 8880，**削减 98.9%**（1000/5000/10000 笔场景分别为 98.8/99.7/99.9%）
- 采集抽稀：合计削减 57.3%（1000Hz 慢写 85.7%，1000Hz 常速 50.0%，240Hz/125Hz 快速书写无削减——本就无可抽）
- 绘制批次：静态层 draw/bind group 10000 笔时 79 → 1
- 镶嵌缓冲复用：1.16x（单次 2.480us → 2.135us）
- 增量镶嵌：每千点耗时 2.49/1.67/2.27 ms 持平 → 确认每点 O(1)，无 O(N²) 退化

## GPU 3D 占用回归修复（静态层前缀增量上传）

用户真机反馈优化后 GPU 3D 占用反升。诊断：`upload_static` 在快照变化（每晾干一笔）时全量重打包整个可见集并从偏移 0 重写缓冲——白板单页笔画全可见，每笔上传量随笔画数线性放大；旧 128 批系统只重传尾部批。

修复（`crates/viewink/src/render/annotation.rs`）：`upload_static` 重写为三路径：
1. 零工作复用：快照 ptr 相同 + 视口在缓存矩形内 → 直接 return；
2. **前缀增量**（书写热路径）：`common_prefix_len` 逐笔比对 (id, generation, geometry Arc ptr)，新快照严格以已持久化快照为前缀且视口位级未动 → 只打包新增可见段，`write_buffer` 写在 `persisted_segs` 偏移处（上传量与新增笔画成正比，恢复旧系统"只传尾部批"特征）；
3. 全量兜底：橡皮擦 targeted rebuild / undo / 视口移动 / 缓冲重建降级。

关键设计点：
- `StaticUploadSlot` 内聚持久化状态：`snapshot: Option<Arc<[StaticStrokeRef]>>`、`persisted_segs`、`cache_view: Option<[f32;4]>`（位级比较——视口移动过哪怕在缓存矩形内也不走增量，避免新旧段剔除标准不一致导致绘制缺失）；`pipeline.static_snapshot` 字段删除。
- 前缀比对可靠性依据：`refresh_static_snapshot` 从 HashMap 按 id 升序重建，几何为同 Arc clone（live_geo.rs 注释已同步更新）。
- cull=false 模式增量同样成立（cache_view=None == view_rect=None）。

验证：viewink 14 测试全绿（新增 `prefix_append_matches_write_then_diverges_on_mid_edit`：追加命中/等长重建/橡皮擦中间修改/undo/首笔不同/空前缀 6 场景）；workspace 全绿；perf 基准 5 项数值无退化（剔除 98.9%、抽稀 57.3%、复用 1.32x）；`cargo check --all-targets` 无代码警告（仅 incremental 锁文件 os error 5 噪音）。

真机复测观测点：`[rstat]` 日志 `static_kb=`（静态层上传字节/秒）——连续书写时应回落到每笔一次增量的水平且不随笔画总量增长；HUD"静态可见 n/m"核对笔画完整性。

## GPU 占用深度优化：静态笔迹离屏光栅化缓存（对齐 Tauri 8%）

用户反馈：修复增量上传后 GPU 3D 占用 60%→40%，目标是 Tauri 版（D:/code/tauri/ViewStage）的 8% 水平。

### Tauri 版 8% 的架构来源（勘察结论）
- 视频：`<video>` DOM 元素直通（camera.js `video.srcObject = stream`）——Chromium 合成器 overlay，GPU 3D 引擎近零开销（解码走 VideoDecode 引擎）；

  - 静止：零 GPU 工作（UpToDate）；

## GPU 占用第二轮：分层诊断与确定成本削减

用户数据：静默 <10%、连续批注 40%+（目标书写也 <10%）。光栅化缓存实测无收益 → 已默认回退几何重放（VIEWSTAGE_STATIC_BLIT=1 可再启用 A/B）。

### 关键发现
- iced 默认 `antialiasing: true` → iced_graphics From 映射为 `MSAAx4`：全部 UI 三角形每帧 4 倍采样 + resolve 读回，每帧固定填充带宽大头（白板层 SDF AA 不依赖它、文字 atlas 采样不依赖它、圆角/边框在 quad shader 内做）。`settings()` 已显式关闭。
- HUD `帧耗时` 文本每帧变化 → 每帧文字 shape/栅格化 + glyph atlas 更新（perf monitor 开启时书写热路径的持续开销）→ 已与 FPS 同窗降频 0.5s。
- 书写限帧已存在（`paced_redraw`，annotation_fps_cap 默认 60）；present 为 AutoVsync。
- 静默 10% vs 书写 40% 的差额主因推断：帧率差（静默低频重绘 vs 书写 vsync 满帧）+ 每帧固定成本（MSAA resolve 等）；每帧成本的削减对所有帧生效。

## 完全笔锋算法重写：自适应胶囊合并（性能第一）

**参照调研**（D:\希沃视频 = CVTE/希沃绘画框架源码，Explore 代理完成）：希沃笔锋 = 压力驱动（无速度映射，`1.5p+0.25` 归一化）+ 椭圆节点外公切 quad + **FuzzyContains 节点合并**（包围盒重叠 ≥95% 跳过轮廓）+ 16 点分段固化增量渲染 + MCU 板载芯片补线低延迟层（WearTime 60ms）。硬件加速路径实为 WPF Visual 双线程，非 D3D。

**现状诊断**（批注 GPU 成本解剖）：
- 静态层每帧全量实例化重放（离屏光栅缓存真机实测无收益已禁用）= 主导项
- 几何密度过高：每输入段 CR 细分 `clamp(ceil(len/6),2,8)`（短段强制拆 2）+ 胶囊圆头 overdraw 2~4×；500 点笔画 ≈ 874 段
- 直播增量路径已 O(1)/点，无需动

**重写实施**（viewink/ink/mesh.rs）：
1. `append_stroke` 重写为**自适应胶囊合并发射**（`extend_run`/`can_merge`/`emit_run`）：贪心合并连续采样点为长胶囊。容差：弦偏差 ≤0.5 画布px（**到弦线段距离**，防回折笔画缺段）、宽度插值误差 ≤0.3px、全宽 <1.5px（极细笔尾）不合并、run 上限 32 采样。橡皮擦切口/零宽断点强制断链（prev_end 连续性检查），绝不桥接擦除间隙。
2. `subdivide_segment*` 改 out-param 零分配；CR 细分下限 2→1（亚 6px 短段不再强制拆 2）。
3. **直播路径不变**（增量不变量与批边界无缝性保留），合并只作用于静态构建（晾干/擦除重建/undo 全部 5 个调用点走 tessellate_stroke_canvas 自动生效）。
